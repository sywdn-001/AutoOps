## 1. 总体目标

### 子任务 A：审计流水不可篡改（硬核）

三张流水表（audit\_logs / command\_logs / file\_logs）的每一行新增
`prev_hash`、`entry_hash`（64 小写 hex，HMAC-SHA256）。新写入的记录按 id 升序单向挂链，
任意行字段被改 / 哈希被改 / 连接关系被改 → 逐行校验立即检出。
老库升级时：schema\_sync 自动 `ALTER TABLE ADD COLUMN DEFAULT ''`，老行两列空串视为
「升级前历史遗留」，verify 跳过不报错，兼容线上已有数据。

### 子任务 UI：审计页视觉升级（美观 + 可视化）

在「审计中心 · 操作日志」顶部新增**卡片式链完整性徽标**（healthy → 翡翠绿渐变；
异常 → 玫瑰-橙渐变），展示三张流水表的总 / 已哈希 / 末尾哈希。列表、抽屉中
category / action / result 统一中文 Tag，抽屉增加独立「链式哈希」色块，显示
prevHash / entryHash（短 8…8 + Tooltip 完整 64 hex + 是否遗留 / 是否未哈希）。

## 4. 兼容性与风险

1. **老数据兼容**：entry\_hash 空串视为升级前遗留，verify 不报错，避免上线即「红」。
2. **写放大可接受**：每条新写入增加 2 次 ORM query（`before_id` 查上一条 + 本身 flush），
   append-only 流水影响可忽略；必要时可后续 batch 写入加缓存 head。
3. **密钥绑定**：哈希绑定服务器 SECRET\_KEY，换 key 会导致老链 verify 失败，上线后
   SECRET\_KEY 禁止变更（或变更时重算全链工具脚本）。
4. **UI 纯追加**：新增 `prevHash/entryHash` 为 `AuditItem` 新字段（后端给值，老后端
   不会给，前端兼容用 `?? ''` / optional），双向兼容。
