# 二·五、关于「超级管理员」的准入例外

堡垒机默认严格按授权表放行。但**超级管理员**（`is_superuser`，即内置 `admin` 角色）在**没有任何授权记录**时，也能在网页终端与 SSH 网关看到并连上「已启用的主机」——否则新部署的环境里，管理员第一件事就是被自己的产品挡在门外。

例外是**受控**的，只放宽「能不能进」，不放宽「能干什么」：

- 仅 `is_superuser` 生效；`ops`/`viewer` 没有授权依旧看不到任何主机（`tests/test_access.py::test_regular_user_still_requires_grant` 守着这条线）。
- 会话**照常落库**（`source=web`/`gateway`），每条命令与输出**照常记录**，命令策略按系统默认策略**照常强制执行**。
- 临时授权不落库（不会污染授权表，会话记录的 `grant_id` 为空），也不会把别的账号借给管理员（`test_superuser_never_borrows_account_from_another_host`）。
- 主机若没有可用资产账号，准入校验会直接拒绝并提示「该主机下没有可用账号，请联系管理员配置资产账号」，不让人白连一次。

# 三、使用流程

## 管理员：先把「谁能碰什么」配好

1. **资产管理** → 主机列表：新增主机（名称/地址/端口/分组/系统类型），再为该主机添加**资产账号**（口令或私钥，落库即加密），并可一键「连通性测试」真实跑一次 `uname -a`。
2. **身份与权限** → 角色/用户：新建用户并指派角色（内置 `admin`/`ops`/`auditor`/`viewer`，也可自定义权限码）。
3. **访问授权**：给用户配置「用户 × 主机（× 账号）」授权，勾选 `登录`/`SFTP`/`上传`/`下载`/**允许改文件**/`网页终端`/`端口转发`，设置时间窗、星期、过期时间、并发上限，并**绑定命令策略与文件策略**（文件策略留空表示用系统默认策略；开关决定「能不能用」，策略决定「能碰哪些路径」）；也可用「授权矩阵」一眼看清谁对哪台机器有什么权限，或批量授权。
4. **命令策略**：维护策略与规则（正则/前缀/精确/包含，优先级、风险级别、放行/拦截/需确认），用「命令试算器」在配置前先验证某条命令会被放行还是拦截。
5. **文件策略**：维护「哪条路径上能做哪些文件操作」的策略与规则（glob/正则/前缀/包含，优先级首条命中，`*` 表示全部操作，风险级别，默认放行或默认拒绝），内置「默认文件策略·敏感路径拦截」（放行常规运维操作，拦截 `.ssh`、凭据文件、系统目录写入等）与「只读浏览策略」；同页可用「文件操作试算器」在绑定前先验证某条路径上的某个操作会被放行还是拦下（重命名/移动/复制会同时校验源路径与目标路径）。
6. **系统设置 / SSH 网关**：查看网关运行状态与主机指纹，调整会话超时、命令超时、登录失败锁定、并发上限等参数。页面上并排显示握手两端的版本号：**服务器版本**（网关自己对外声明的 `SSH-2.0-BastionGW_1.0`）与**客户端版本**（堡垒机作为客户端去连目标机时声明的 `SSH-2.0-paramiko_<版本>`）；同一个「客户端版本」也会出现在**主机 → 账号 → 连通性测试**的结果里，方便排查「对端不认我们的客户端版本」这类问题。

## 运维人员：几种接入方式，同一套审计

**方式 A · 网页终端（一个弹窗 = 一条会话）**

`网页终端` 是一个**资产列表页**：选好账号后点「连接」，浏览器会用 **`window.open()` 弹出一个独立终端窗口**（第三参数带 `popup=yes` 与尺寸，居中、可缩放，形态对齐 JumpServer），一个窗口只跑一条审计会话；关掉窗口即结束会话。控制台按 JumpServer `luna` 的控制台形态重做：

- **一条会话一个弹窗**：页面里不再堆多个会话，也不再实时铺审计/命令日志（那些去「审计中心 → 会话记录 / 命令记录」看）；资产列表页本身不内嵌终端，只负责选资产、选账号、开窗口。每次点「连接」都是一个新窗口（窗口名带时间戳），所以「一连接一窗口一会话」。
- **工具条**：资产列表（关掉本窗口回到列表）、资产名、状态、账号、会话号、**文件管理**（弹出 SFTP 可视化文件管理器独立窗口）、重新连接、搜索、字号增减、纯净模式、工作区全屏、快捷键说明、断开会话。
- **键盘**：`Ctrl/Cmd+F` 搜索、`Ctrl/Cmd+Shift+C` 复制选中、纯 `Ctrl+C` 发中断、`Ctrl/Cmd+V` 粘贴、`Ctrl/Cmd+Shift+F` 全屏、`Ctrl/Cmd+Shift+P` 纯净模式、`Ctrl/Cmd+Shift+A` 回到资产列表（关闭本窗口）（还有 Esc 长按 800ms 退出纯净/全屏）。
- **终端内右键菜单**：复制 / 粘贴 / 全选 / 清空屏幕 / 放大字号 / 缩小字号 / 全屏 / 断开或重新连接。
- **断开即关窗**：点「断开」（或会话在服务端结束）后，终端里出现 `本窗口将在 10 秒后自动关闭…` 的**原地倒计时**（逐秒刷新，不刷屏），数到 0 自动关掉窗口；浏览器只允许脚本打开的窗口自关，被拒时提示手动关闭（`Ctrl/Cmd+W`）。倒计时结束前点「重新连接」可以取消关闭继续用这个窗口；**网络掉线不算断开**，不会关窗，仍可「重新连接」。
- **底部状态条**：登录态圆点 + 用户名｜当前资产名与协议｜状态（已连接/连接中/已断开/连接失败，含断线原因）｜**连接时长每秒刷新**。

**方式 A 之姊妹功能 · 文件管理器（SFTP，可视化，每步都审计）**

终端工具条上点「文件管理」，会像终端一样**再弹一个独立窗口**（`/files/console`，同一条授权、独立 SFTP 会话）：

- **可视化浏览**：进入即为该授权的主目录，面包屑可逐级跳转，表格列出名称/类型/大小/权限/修改时间，双击目录进入、支持刷新与排序；窗口标题带主机名，工具条显示账号、**当前生效的文件策略名**与会话号。
- **能做的操作**：上传（多文件，**带实时进度面板**：每个文件一行，显示文件名 / 已传字节 / 百分比 / 实时速率，可随时点 ✕ 取消）、下载（单文件 + 打包下载 zip）、在线编辑并保存（带 mtime 冲突检测，文件被别人改过则拒绝覆盖）、新建文件/新建目录/重命名/移动/复制/删除（多选）、改权限（4 位八进制）。
- **两道闸一起判**：① `Grant` 授权开关——`SFTP` 决定能不能进这个窗口，`上传`/`下载`/`允许改文件` 决定具体动作，没开的按钮直接置灰并说明原因；② **文件策略**——按路径匹配规则（`glob`/正则/前缀/包含，优先级首条命中）判定该操作在该路径上是否允许，重命名/移动/复制会同时校验源路径与**目标路径**，任一被拦即整条拒绝。**已经打开的窗口也实时跟随授权变更**：管理员把「允许改文件」或 `SFTP` 关掉，下一次操作当场被拒（不需要重开窗口）。
- **拒绝可见**：被拦时窗口内直接给出原因（如 `文件操作被策略「默认文件策略·敏感路径拦截」拦截：操作 [read] 源路径 [/.ssh/id_rsa] 命中规则 #1：禁止通过文件管理器访问 .ssh 目录`），不是静默失败。
- **全量留痕**：每一次操作——**放行、被拒、失败**三种结果都写一条文件审计（用户/主机/会话号/操作/路径/目标路径/动作/风险级别/命中规则号与规则文本/原因/结果/字节数/耗时），并同时计入会话审计（`protocol=sftp`）；失败也会留痕（例如打包一个不存在的路径 → 404 并记一条 `result=failure`）。窗口关掉即结束 SFTP 会话，「文件记录」页可查。
- **关闭**：点「关闭」或关掉窗口结束会话，窗口内同样有倒计时与「返回资产列表」兜底。

**方式 D · RDP 网关（Windows 自带的 mstsc，不用装客户端）**

前面三种都是「浏览器里」的入口；如果运维手上只有 Windows 自带的「远程桌面连接」，用这个：

```
mstsc /v:<堡垒机地址>:4489
```

- **登录页在会话里**：连上 4489 先看到网关自己画的登录页，输入**堡垒机账号口令**（和网页登录同一个账号），
  第一次连会提示证书不受信任（网关自签），点「是」继续；
- **选单只列有权限的机器**：登录成功后是「你有权访问的主机」列表，`↑↓` 选择、`Enter` 连接、鼠标点哪行选哪行；
- **目标机画面接进同一窗口**：选中后网关自己当 RDP 客户端去连目标机的 3389，把画面接到这条会话里，
  键盘鼠标都能用（`Esc` 是「回到选单」，不转发给目标机）；
- **口令不出堡垒机**：目标机账号口令由后端解密后只交给网关进程，取用时写一条
  `rdp_credential_reveal` 审计；会话本身在「审计中心 → 会话记录」里是一条 `source=gateway, protocol=rdp`；
- **安装与开关**：RDP 网关已解耦为官方扩展模块，先在「系统设置 → 扩展模块」安装
  `rdp-gateway-<版本>.mod.ops_ext` 并启用；开关与端口在模块页面的「模块设置」里
  （`mod.rdp-gateway.enabled` / `mod.rdp-gateway.port`），页面上也能看运行状态、启动/停止/诊断与日志；
- 细节（架构、配置项、日志读法、自己编译、已知限制）见 [RDP网关.md](RDP网关.md)。

**方式 B · SSH 网关**

```bash
ssh -p 2222 <堡垒机账号>@<堡垒机IP>
```

登录后进入审计菜单：

```
=== AutoOps 堡垒机 审计网关 ===
 1) web-01        10.0.0.11:22    [生产]  策略:标准运维策略  账号: root, deploy
 2) db-01         10.0.0.21:22    [数据库] 策略:高危需确认    账号: dba
请输入主机编号（l 刷新 / i 我的信息 / h 帮助 / q 退出）:
```

选择编号 → （多账号时）选择账号 → 进入该主机的 shell，每条命令都会经过策略判定并被记录。

**方式 A 与方式 B 都能连 Windows 主机（WinRM，字符会话）**

Windows 主机只要协议配成 `winrm`（默认端口 5985，认证方式 `ntlm`），就会和 Linux 主机一起出现在**网页终端那张资产列表**里（地址列标注「· WinRM 网页终端」，状态栏显示 `WINRM`），也会出现在**SSH 网关的主机菜单**里 —— 两条入口进的都是 PowerShell 字符会话：`cd` 会保留，`exit` 退出会话回到菜单（`q` 退出网关）。命令与输出照旧逐条进「命令记录」与会话转录（`sessions.protocol='winrm'`）。

三条能力边界会**在会话建立时直接写在终端里**（网关与网页终端同一措辞），而不是让用户自己撞墙：

- **每条命令在目标机上单独执行**（WSMan 是无状态的）：`cd` 由堡垒机记住并复原，但环境变量、自定义变量等进程内状态不保留；
- **`more` / `pause` / `Read-Host` 这类交互式程序不可用** —— 需要交互的活儿请改用远程桌面；
- **不支持文件传输**（WinRM 没有 SFTP 通道）：WinRM 会话的工具条上**没有「文件管理」按钮**，传文件请改用 Linux 主机或远程桌面。

## 一·八·补、一台主机、多个协议入口（A + B）

一台机器同时有 RDP（要画面）和 WinRM（要命令审计）是常态，但按「一条主机记录一个协议」的建模，就得把同一台机器建成两条记录 —— 用户实测反馈的原话是「都是同一台主机，只是协议不同就要搞两个条目，太麻烦了」。所以做了两件事：

- **A · 数据模型：一台主机挂多个协议端点**。新增 `host_protocols` 表（`uq_host_protocol(host_id, protocol)` 钉住「同协议只有一条」），每行是 `protocol` + `port` + `winrm_transport` + `status`；`hosts` 表原有的 `protocol` / `port` / `winrm_transport` 退役成**镜像字段**（始终指向主端点），老代码路径 `host.port` 照常可用。协议端点、账号、授权都挂在**同一台主机**上，`sessions.host_id` 与审计口径完全不变（历史会话不会被搬家改写）。
- **B · 界面：同一条记录就是一个条目**。主机表单的「协议入口」是**多选**，选中哪个协议就出现哪个协议的端口输入（WinRM 端口 / RDP 端口 / SSH 端口各自独立）；主机列表的地址列逐端点列出 `地址:端口`、协议列逐端点打标签；**网页终端入口页按 `hostId` 合并成一行，行内每个协议一颗入口按钮**（`连接` / `WinRM` / `远程桌面`），只有 SSH 端点才带「文件」按钮；点进去的控制台地址带上 `?protocol=`，服务端按该端点建会话（`open_session(protocol=…)`），网关菜单同样把端点协议传下去。

配套两个后端动作：

| 动作 | 接口 | 说明 |
| --- | --- | --- |
| **合并两台同地址主机** | `POST /api/hosts/<id>/merge`（管理员） | 把「同一台机器的另一条记录」并进本机：账号、授权、协议端点全部搬过来（同名**且同一把凭据**的账号复用，同名不同凭据的改名保留 —— 绝不因为重名丢掉凭据），随后删除来源记录。地址不同直接 400，来源机还有在线会话则 409。前端在主机列表的操作列有「合并」按钮，弹窗只列出**同地址**的其它主机 |
| **老库回填端点** | 启动时自动 | `backfill_host_protocols()` 在 `ensure_schema()` 之后跑：哪台主机还没有端点行，就按它的镜像字段补一条；已有端点的机器**跳过**（幂等，管理员手工配过多协议的不被覆盖） |

**方式 C · Windows 远程桌面（WebRDP）**

Windows 主机就排在**「网页终端」同一张资产列表**里（系统图标区分平台，不额外加标注）：点「连接」用 `window.open()` 弹出**独立控制台窗口**（`/rdp/console`，`layout:false` 不进菜单），一个窗口只跑一条审计会话。顶栏可以收起给画面让位；画面随窗口大小自适应 —— 拉大浏览器窗口时被控主机也会换到新分辨率（不是把画面拉伸）；**会话断开后弹 10 秒倒计时自动关窗**（和 Linux 网页终端断开后的行为一致），录像自动上传。

- **谁在画**：浏览器里跑 `ironrdp-wasm`（第三方库，Rust 版 IronRDP 编译成 WASM），RDP 协议栈完全在客户端侧实现，画面直接进 `<canvas>`；堡垒机只做 RDCleanPath 字节中继，不解码画面。
- **怎么授权**：与终端完全同源 —— `rdp:use` 权限码 + 该主机的 `Grant`（授权范围内的账号、时段/星期/过期/并发上限）+ `canWebterm` 开关；主机协议必须是 `rdp`，账号必须是口令认证。
- **口令从哪来**：操作员**不需要知道**目标机口令 —— 堡垒机用 Fernet 解出资产口令，随 120 秒一次性票据下发给浏览器（NLA/CredSSP 必须在客户端算），并**专门写一条 `rdp_credential_reveal` 审计**：「谁在什么时候把哪台机器的哪个账号口令交给了浏览器」。
- **留痕**：`rdp_ticket`（申请票据）→ `rdp_credential_reveal`（口令下发）→ `rdp_session_open`（会话建立，含协商结果与服务器证书）→ `rdp_session_close`（断开原因、上下行字节数、时长），四个动作都在审计中心的会话/操作日志里可查。
- **能回看**：远程操作全过程在浏览器侧录成 webm（`canvas.captureStream()` + `MediaRecorder`），**边录边传** —— 每 5 秒把分片 `POST /api/rdp/recordings/chunk` 按序追加进服务端暂存文件，正常结束走 `finalize` 原子改名转正；窗口被强行关掉（直接关标签页 / 崩溃 / 断网）时前端来不及 finalize，服务端会在「有人打开录像列表 / 有人开新远程桌面」时把静默超过 45 秒的任务**自动收口**成录像并标成「未正常结束」（`recovered=true`），整段视频不再凭空消失；「审计中心 → 远程桌面录像」按操作人/资产账号/时长/体积/时间列出，点「回看」换一张 10 分钟票据流式播放（`<video>` 带不了 `Authorization` 头，所以走 `?ticket=`），每次回看、每次删除都会另外留一条审计。

## 审计员

`审计中心` → 会话记录（含**在线会话强制中断**、详情三视图：概要 / 命令记录 / 录像回放）、命令记录（命令、输出、放行或拦截、命中规则、风险、耗时）、**文件记录**（文件管理器里的每一次操作：用户/主机/会话/操作/路径/目标路径/动作/风险/命中规则/结果/字节数/耗时，可按用户/主机/会话号/操作/结果/风险筛选）、操作日志（登录、资产变更、授权变更、策略变更、会话建立与中断等）。

**清除审计数据（仅管理员）**：四个审计页（会话 / 命令 / **文件** / 操作日志）都支持勾选后「删除选中」，或按当前筛选条件「清除筛选结果」（未设置筛选即清空全部）。会话清除会**级联删除**该会话的命令日志与录像文件，**进行中的会话会被跳过**（提示先中断再清除）；每一次清除动作本身都会写入一条审计留痕（`purge_audits` / `purge_commands` / `purge_files` / `purge_sessions`），所以「谁在什么时候清掉了什么」也可追溯。**文件记录的清除需要 `command:view_all`**：内置 `ops`/`admin` 有，`viewer`/`auditor` 没有（`tools/live_e2e_check.py` 用 `e2e-viewer` 实测 403）。

## AI 运维助手（两种入口，同一套权限与审计）

AI 助手不是「另一个管理员」：它调用的每一个工具都是**带着当前登录者的身份**去打堡垒机自己的接口，所以**这个人在网页上做不了的事，问 AI 也做不了**；敏感操作还要额外过一道管理员口令。

**入口 A · 网页「AI 运维」页**（`/ai`，需要 `ai:use`）

- **左侧对话列表 + 右侧消息流**：新建/切换/删除会话，历史对话随时回看（模型、关联主机、消息数、工具调用数都记在会话上）。
- **流式 Markdown**：答案逐字长出来（思考过程单独折叠展示），代码块、表格、列表正常渲染；模型给的**卡片**就地渲染成真正的 antd 组件（主机清单表格、修改结果键值、风险告警、执行步骤）。
- **工具调用可见**：每次工具调用都在气泡里留下一张可展开的记录（工具名 / 入参 / 结果 / 耗时 / 是否敏感），失败也会显示原因。
- **敏感操作要口令**：命中 `sensitive` 工具时弹出**管理员账号 + 密码**确认框（列出即将执行的操作与参数），拒绝即中止，确认后同一轮对话继续跑；口令错误直接判为拒绝并留痕。
- **「AI 能用什么」抽屉**：按分组列出**当前账号**实际可用的工具清单（权限不够的工具根本不在列表里）。
- **单轮工具调用上限可调**：一个回合里最多几轮「模型要工具 → 执行 → 回灌」由 **系统设置 → 参数设置** 里的「**AI 任务最大调用轮数**」（`ai_max_tool_rounds`，默认 8、可填 1–50）决定，**保存即生效、不用重启后端**（`.env` 的 `AI_MAX_TOOL_ROUNDS` 只在设置留空时兜底，写进库的离谱值会被夹到 1–50）。撞到上限会停下来补一句「已达到单轮工具调用上限 N 次，先停下来，请确认后继续。」，不会无限自转。

**入口 B · SSH 网关会话内 `/ask-ai`**（先按需求④登录并选好主机）

```
root@demo-linux-01:~# /ask-ai 这台机器磁盘满了吗
```

- 这一行**不会被目标机执行**：网关识别到 `/ask-ai` 前缀后会发一个 `Ctrl-U` 把该行擦掉、**不转发回车**，再向 AI 提问（所以目标机的 shell 历史里不会留下这条命令）。
- 答案在终端里**流式重绘**（原地刷新，不刷屏），Markdown 的标题/列表/代码/表格照常上色；**卡片降级为 ASCII 表格/列表**，终端里不会出现 JSON。
- 触发敏感操作时用**纯文本 + 掩码**逐步确认（不输出任何可交互控件）：`管理员账号：` → `管理员密码：`（不回显），回车即拒绝。
- 对话与工具调用同样落库（`source=shell`，带关联主机与会话号），审计中心一样可查。

**审计**：`审计中心 → AI 对话审计`（`/audit/ai`，需要 `ai:view`）——「AI 对话」页签（对话 / 发起人 / 关联主机 / 消息数 / 工具数 / 最近活动）与「工具调用」页签（时间 / 调用人 / 工具与敏感标记 / 状态 / 确认人 / 入参 / 结果），点「查看详情」可读该对话的**逐条消息**（含思考过程与卡片 JSON）与全部工具调用；只有 `ai:view_all` 才能看到**别人**的对话，否则只看得到自己的。

**第三轮实测反馈的三个修复**（用户原话：「这里明明是 WinRM 远程终端，AI 跑不了命令因为把 WinRM 当 SSH 使了」「添加主机这里协议选择 SSH 底下就不应该出现 RDP 的东西，合并 WinRM 和 RDP，两者都是 windows」）

- **AI 执行命令按端点选通道**：`run_command` 落到的 `POST /api/terminal/exec` 现在按主机的**协议端点**挑通道 —— Linux 端点走 SSH（写 Bash/POSIX 命令）、Windows 端点走 WinRM（写 PowerShell 命令），响应体新增 `channel` / `protocol` 告诉你命令实际跑在哪条通道上；修复前 Windows 主机一律被拿去连 SSH，于是报 `Error reading SSH protocol banner`。工具的说明文字也按系统分通道（让模型知道该写哪种语法），并支持 `protocol` 参数强制指定通道。
- **点名协议必须照办**：显式传了 `protocol` 但该主机没有这个端点时**直接 400**（`NO_CHARACTER_ENDPOINT`，文案列出可用端点），不再静默换一条通道把命令跑掉 —— 否则调用方以为命令跑在 A 通道、实际跑在 B 通道，审计口径就错了。rdp 这类图形端点也会被明确拒绝（「rdp 是图形桌面」）。
- **主机表单协议合并**：「协议入口」合并成 **Linux / Unix（SSH 命令行）** 与 **Windows（命令行 + 远程桌面）** 两项；选 Windows 后再勾「命令行（WinRM / PowerShell）」「远程桌面（RDP）」两个通道（同一台机器可以只开一个、也可以都开），**只有勾了对应通道才出现** `RDP 安全层` / `WinRM 认证方式` 与各自的端口框 —— 选 SSH 时下面不会再冒出 RDP 的东西。

## 一·八·补·二、ComputerUse：让 AI 直接操作一台 Windows 主机

### 这是什么

ComputerUse 是「**让 AI 直接操作一台 Windows 主机**」的功能：在目标机上跑一个开源项目 Windows-MCP（`https://github.com/CursorTouch/Windows-MCP`，PyPI 包名 `windows-mcp`，要求 Python 3.13+），以 `streamable-http` 传输提供 MCP 服务；堡垒机当 MCP 客户端，调它的工具去操作那台机器。

- 20 个工具：App、DisplayInventory、PowerShell、FileSystem、Snapshot、Screenshot、Click、Type、Scroll、Move、Shortcut、Wait、WaitFor、Scrape、MultiSelect、MultiEdit、Clipboard、Process、Notification、Registry。
- 和「AI 运维助手」的区别：AI 运维助手是**堡垒机自己**去查资产、读日志、跑命令；ComputerUse 是 AI **把手伸到别人的桌面上**——看屏幕、点鼠标、敲键盘、开程序。所以它的每一步都要走审计，会改机器状态的工具还要你当场确认。

### 四个入口位置

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 部署向导 | **系统设置 → ComputerUse 部署**（`/system/computer-use`） | 分步向导，把 Windows-MCP 装到纳管的 Windows 主机上 |
| 部署记录 | 同一个页面的「查看记录」按钮 | 抽屉里列出每次部署：主机 / 状态 / 阶段 / 进度 / Python / MCP 地址 / 部署人 / 创建时间 |
| 控制台侧边栏 | **WebRDP 控制台**（`/rdp/console`）右侧 | 折叠时是一条 44px 的竖条，展开后是 400px 的面板；**只有部署成功后**才出现 |
| AI 运维助手 | AI 对话里也能用 ComputerUse 的工具 | `list_computeruse_hosts`、`get_computeruse_status`、`list_computeruse_tools`、`observe_computer`（只读）、`control_computer`（会改机器状态，敏感操作要确认） |

侧边栏不是想开就开的：`GET /api/computer-use/status` 返回 `ready: true`（也就是那台主机上真的探活出一个能用的 MCP）时，面板才渲染出来；否则整块不出现。

### 准备条件

- **目标机**：Windows，并且**已经把 WinRM 开好**（ComputerUse 全程靠 WinRM 推命令过去，和「方式 A 与方式 B 都能连 Windows 主机（WinRM，字符会话）」用的是同一套通道）。
- **一台能用的资产账号**：账号要有管理员权限——装 Python、写 `C:\Program Files`、建防火墙规则、建计划任务，哪一样都少不了。
- **主机要在堡垒机里纳管好**：先在「资产管理」里加好这台主机、**配好 WinRM 端点与认证方式**，ComputerUse 的「选择目标主机」是从**已有资产列表**里挑的，挑不到就得先回去加主机。
- **Python 3.13+**：`windows-mcp` 只兼容 Python 3.13 及以上，向导里的候选版本都按这个筛过。目标机上原本装着 3.9.9 之类**没关系**——新装的那个 3.13 会和它共存，互不打扰。
- **Python 安装包**：从华为云镜像站（`https://mirrors.huaweicloud.com/python/`）列版本，**先缓存到堡垒机**，再由目标机带签名地址拉走（见下面第 1 步）。
- **网络**：目标机要能访问堡垒机（下载安装包），能访问 PyPI 或你指定的 pip 源；部署完之后**只有堡垒机**能访问目标机的 8000 端口。

### 四步操作流程

打开 **系统设置 → ComputerUse 部署**，就是一个四步向导（进度条上写着「选择 Python 安装包 → 选择目标主机 → 执行部署 → 完成」）。中途随时可以「重新开始」，顶部的「查看记录」能回看历史部署。

**第 1 步 · 选择 Python 安装包并缓存到堡垒机**

- 列表按版本列出来自 `https://mirrors.huaweicloud.com/python/` 的 Windows AMD64 安装包，挑一个 **≥ 3.13** 的版本。
- 点缓存，安装包会落到堡垒机的 `bastion-backend/instance/computeruse/installers/`，同时写下 `.sha256` 与 `.meta.json`。这一步是**先存到堡垒机**——后面目标机不用自己去连华为云镜像。
- 华为云镜像站**新建连接**的首包要 **20–36 秒**，复用同一条 keep-alive 连接只要 **0.1 秒**，所以探测是串行复用连接的，总预算 25 秒；超了预算会先交出已经探到的部分结果，剩下的在后台慢慢预热。缓存时间分两种：**完整的目录缓存 1 小时，不完整的 2 分钟**。
- 已经缓存过的安装包可以删（对具体文件名删，不影响别人）。

**第 2 步 · 选择目标主机与资产账号，顺手把部署选项调好**

- 从纳管主机里挑一台**启用了 WinRM 的 Windows 主机**和它的资产账号。
- 部署选项（有默认值，一般不用动）：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| MCP 端口 `mcpPort` | `8000` | 目标机上 MCP 监听的端口 |
| pip 源 `pipIndex` | `https://pypi.tuna.tsinghua.edu.cn/simple` | 装 `windows-mcp` 用哪个源 |
| 访问密钥 `useAuthKey` | 开 | 给 MCP 加一层 Bearer 密钥 |
| 监听所有网卡 `bindAll` | 关 | 关掉时 MCP 只听 `127.0.0.1`，靠 portproxy 对外 |

- 关于 pip 源：清华源装 `pip install windows-mcp` 大约 **5 秒**，**直连 pypi.org 实测约 18 分钟**，所以默认填的是清华源。

**第 3 步 · 开始部署，看阶段进度与实时日志**

- 点「开始部署」后，页面把进度条与日志一起推给你（日志走 SSE：`GET /api/computer-use/deployments/<id>/logs`，事件一条条往下滚，不用刷新）。
- 同一个时刻**最多 2 个部署在跑**（`MAX_CONCURRENT = 2`）——WinRM 连接加上 pip 都很吃目标机。
- 跑到一半不想要了，可以取消（`POST /api/computer-use/deployments/<id>/cancel`），状态会记成「已取消」。
- 记录会存在 `computeruse_deployments` 表里：主机、账号、安装包、Python 路径、MCP 地址/端口/工具清单、状态、阶段、进度、日志尾巴、起止时间等。访问密钥用 Fernet 加密存进 `mcp_auth_key_enc`，**不落明文**。

**第 4 步 · 成功页**

- 全部跑完会显示成功页：MCP 地址、Python 路径、工具清单，以及一颗「**打开 WebRDP 控制台**」按钮（它会带着 `hostId` 跳到 `/rdp/console`）。
- 成功页上那句话是认真的：「控制台要在部署成功后才能打开」——侧边栏只认探活成功的部署。

### 八个阶段

进度条上的八个阶段就是后端真正执行的八件事（前端进度条和后端执行顺序读的是同一张表）：

| 阶段 | 名字 | 锚点进度 | 干了什么 |
| --- | --- | --- | --- |
| `prepare` | 连接目标机 / 环境体检 | 6 | 连上去体检：OS、架构、PowerShell、磁盘、已有的 Python 与 MCP |
| `upload` | 把 Python 安装包传到 `C:\Installer` | 28 | 目标机从堡垒机的签名地址把安装包拉到 `C:\Installer\`，拉完校验大小与 SHA256 |
| `install` | 静默安装 Python（`/quiet InstallAllUsers=1 PrependPath=1`） | 48 | 静默装，装完回读新 Python 的路径与版本 |
| `pip` | 安装 windows-mcp（pip） | 68 | 先升 pip，再 `pip install windows-mcp`，装完回读版本与 `windows-mcp.exe` 路径 |
| `vbs` | 写开机自启 VBS 并立即启动 MCP | 82 | 写开机自启脚本，写命令是 `windows-mcp serve --transport streamable-http --host localhost --port 8000`，写完**立即**启动并等它真的监听上 `127.0.0.1:8000` |
| `expose` | 开 portproxy（局域网地址 → 回环） | 92 | 挑一张**默认路由那侧**的内网地址（老实现只取第一个地址，多网卡机器上常挑到堡垒机到不了的网卡），把 `IP Helper`（iphlpsvc）拉成自动启动并跑起来，再 `netsh interface portproxy add v4tov4` 把「内网地址:端口 → 127.0.0.1:端口」映射好，最后读回监听地址 |
| `firewall` | 放行 MCP 端口（只放行堡垒机 IP） | 96 | 在目标机入站方向放行 MCP 端口（来源只写堡垒机 IP，识别不到堡垒机 IP 时退化为 `LocalSubnet`），**写完用 `Get-NetFirewallRule` 读回来逐项核对**（规则在不在、启没启用、方向/动作/协议/端口/来源对不对，netsh 写不上就退到 `New-NetFirewallRule` 重写一遍），核对通过后**再从堡垒机侧真的连一次**目标机的端口——连不上就让部署失败 |
| `verify` | 探活 MCP（`tools/list`） | 100 | 用 MCP 客户端探活，把工具清单写回数据库 |

> 为什么放行防火墙要单独一个阶段、还要读回核对：`netsh advfirewall firewall add rule` **不校验返回码也不回读**，以前它夹在 `expose` 里，加失败也照样往下走，最后就是「部署显示成功、侧边栏却连不上 MCP」。现在这一步失败会让整次部署失败，报错里直接给出手工复核命令（`netsh advfirewall firewall add rule name=AutoOps-ComputerUse dir=in action=allow protocol=TCP localport=<端口> remoteip=<堡垒机IP>`）与三条常见原因（MCP 进程没在跑 / portproxy 没生效 / 端口被占）。


### 侧边栏怎么用

部署成功之后，从成功页跳进 WebRDP 控制台（或者自己开 `/rdp/console`），右侧就多出一条 **44px** 的竖排条，点开是 **400px** 的面板（展开/收起的状态记在浏览器里，刷新还在）。

- **截图自己回到对话里**：不用再手点按钮。AI 调 `Screenshot` / `observe_computer` 拿到 PNG 之后，后端会把图**抽成一张图片卡片**贴在那次工具调用下面（它自己只看得到「这里有一张图」的占位，8 万字符的 base64 不再回灌上下文挤爆对话）。真机上后端直接调 `POST /api/computer-use/mcp/call` 的 `Screenshot` 回来的是一张 **106,018 字节、1024×768** 的桌面图（后端 pillow），耗时 **790 ms**——见 [computeruse-mcp-screenshot.png](screenshots/computeruse-mcp-screenshot.png)。抓不到像素时面板会把原因写出来（多数是目标机当前**没有已登录的桌面会话**）。
- **重启 MCP**：面板头部那颗「重启 MCP」按钮会打 `POST /api/computer-use/mcp/restart`。目标机上的 MCP 卡住（典型是取 UI 元素树把服务卡死）或者你刚登录桌面、想把 MCP 接管到自己的会话时点它：服务端杀掉旧进程、用开机自启脚本重新拉起、再探活一次，成功后把工具数刷回面板。面板每 30 秒问一次状态，一次 MCP 调用最多等 60 秒（重启最长等 180 秒）。
  - **它只会杀 MCP 自己**：按进程名白名单（`python` / `pythonw` / `windows-mcp`）且命令行要匹配 `windows-mcp` 才动手，白名单外的一律跳过并在回显里留 `SKIPPED=<pid>:<名字>`。这条是血的教训：8000 端口上的**第一个监听者往往是 portproxy 的 `svchost`（iphlpsvc）**，早先不看进程名就杀，会把 portproxy 一起干掉，堡垒机侧随即从「能连」变成 `10061 积极拒绝`。
  - **它也不信「端口有人听」**：portproxy 自己也监听这个端口，所以「MCP 起来了」只认**回环地址**（`127.0.0.1` / `::1`）上、进程名在白名单里的监听者；顺带读回一次 portproxy（被杀了就自动把 `iphlpsvc` 拉起来、重建映射）。
  - **成功长什么样**：只有「回环上真有 MCP 进程 + portproxy 活着 + **堡垒机侧探活通过**」三条都满足才报成功；否则面板报失败并给出具体原因（`目标机上没有新的 MCP 进程监听回环端口…` / `MCP 已经起来，但 portproxy（IP Helper）没有在目标机的局域网地址上监听…` / `MCP 进程起来了，但堡垒机探活仍然失败：…`）。真机实测一次重启约 **24 秒**，返回里带 `killedPid`（真 MCP）、`skippedPid`（被跳过的 portproxy 之类）、`proxy` / `proxyAddress` / `proxyService`。
- **可用工具数**：面板头部直接写着这台目标机上报了多少个工具（真机上是 20 个）。**工具清单不再在面板里摊开占版面**；要逐条看标记（标「**只读**」的 AI 可以直接调用，标「**会改机器状态**」的点击、输入、PowerShell、注册表、文件系统……AI 调用时要管理员当场确认），走 AI 运维助手的 `list_computeruse_tools`。
- **AI 对话**（对齐主界面「AI 运维助手」）：面板下半截就是聊天框，可以边看屏幕边让它干活——正文流式长出来（**Markdown 真的渲染成 DOM**：无序/有序列表、表格、引用、行内代码、加粗；卡片与代码块跟 AI 运维页**共用同一套** `bastion-ai-*` 组件与深色配色），**思维链（「思考过程」）和每次工具调用（「工具调用 N 次」）各是一块折叠区、默认展开**，看完可以收起来；干活时显示「正在思考…」，答完给一行「用时 X.Xs」（一轮里工具调用撞到上限会补一句「已达单轮工具调用上限」）。工具卡里能看到「成功/失败」标签、工具名、耗时、确认人、参数与结果预览，要改机器状态的调用还会带「待确认 N」角标。**一条回答按轮分段**：每一轮的「思考过程 → 工具调用 → 这一轮的正文」依次往下排（每一块带自己的 `data-round`），不再把整轮的思考与工具都堆在最前面。
- **示例问题**：还没聊过时面板给出 4 条示例（「打开记事本，输入今天的巡检结论」「把当前屏幕截一张给我看」等），**点一下就发出去**。
- **输入区**：输入框和「发送」按钮**同一行**（按钮在右），回车发送、Shift+回车换行；回复过程中按钮换成「停止」。
- **写操作要确认**：命中会改机器状态的工具时弹确认框，要填管理员账号（本机登录的管理员可以留空）与密码，「拒绝执行 / 确认执行」二选一，确认后同一轮对话接着跑。**确认之后的续流会落回原来那条回答**：工具卡当场从「待管理员确认」翻成「已确认，执行中」再到「成功」，后面的思考与工具卡继续长在同一条气泡里；拒绝同理（卡片标「已拒绝」，并补一句「未执行」）。
- 面板脚下那行提示请务必当真：「AI 操作的是目标机的控制台会话；与当前 RDP 会话可能是两个桌面，请以截图为准。」
- 侧边栏自己有错误边界：它出问题只会把侧边栏吞掉，不会连累你正在用的 RDP 会话。

### 安全与审计

- **只监听回环，再映射出来**：MCP 默认只听 `127.0.0.1:8000`，用 `netsh interface portproxy` 映射到局域网地址；**防火墙只放行堡垒机那一个 IP**。万一探不到堡垒机 IP，就退化成只放行本网段，并在日志里挂一条 warning（不静默）。
- **可选访问密钥**：给 MCP 加一层 Bearer 密钥，密钥用 Fernet 加密后存库（`mcp_auth_key_enc`），不落明文。
- **签名临时下载地址**：目标机拉安装包用的是一个 **HMAC-SHA256 签名 + 2 小时有效期**的临时地址（`GET /api/computer-use/installers/<文件名>?e=…&s=…`），只对**具体文件名**有效——目标机没有 JWT 也能下，但换个文件名就下不动。
- **每次都写审计**：每一个阶段、每一次探活、**每一次 MCP 工具调用**都落进 `audit_logs`（分类 `computeruse`：`deploy_start`、`deploy_stale`、`mcp_probe`、`mcp_call`、`cache_installer` 等），审计链可校验。
- **权限**：`computeruse:view`、`computeruse:deploy`、`computeruse:use` 三个权限在系统设置的角色/权限里勾（后端每个接口都会校验）。

### 常见问题与限制

**「部署成功了，但截图是空白的？」——会话隔离，这是最容易踩的一条**

Windows-MCP 的截图与界面自动化只认「**它自己所在的那个登录会话**」。目标机上**没有交互式登录**时，MCP 跑在会话 0：PowerShell、文件、进程类工具都能用，但**截图和界面自动化是空的**。你从「WebRDP 控制台」RDP 登录进去之后，开机自启脚本会用「端口接管脚本」把 MCP **抢到你的桌面会话**（**同一个端口，侧边栏不用改地址**），之后截图就是你眼前那个桌面了。

**pip 装得很慢？**

`pip install windows-mcp` 直连 pypi.org 实测约 **18 分钟**；换成清华源大约 **5 秒**。向导默认填的就是清华源，别手滑改成直连。

**其它常见坑**

- 挑不到主机：先在资产管理里把那台 Windows 主机加上，**把 WinRM 端点配好**。
- 版本列表拉不出来：华为云镜像站新建连接首包要 20–36 秒，稍等一下；超预算时列表会先给你一部分。
- 部署卡在 `running`：后端重启或线程异常会留下僵尸 running 记录，新建部署时会被自动判成 `failed`（审计记 `deploy_stale`），重新发一次就行。

**本次已知限制（如实写，不吹）**

- **浏览器目视验收：2026-10-13 首轮 + 2026-10-14 改版轮都做了**（Chrome 155.0.8059.40，CDP 驱动真实页面，真机 `hostId=5` 的 `/rdp/console`，跑的就是当轮代码）：首轮验面板展开、示例问题点一下就发出、思维链与「工具调用 1 次」随流式依次出现、敏感操作确认弹窗自动弹出；改版轮验「看一眼屏幕」按钮与截图区块已消失、「重启 MCP」已在头部、深色主题下**没有黑字**（按钮 / Tag / 折叠区都走 antd 深色 token；另做了一次全量对比度体检：面板里 **73** 个自带文字的元素，纯黑 `rgb(0,0,0)` **0** 个、WCAG 对比度 <3.0 的 **0** 个）、轮次结构换成 AI 运维那套（`bastion-ai-turn`、折叠区 `bastion-ai-collar`、工具卡 `bastion-ai-tool`）、**Markdown 真的渲染成 DOM**（`ul=1`、`li=3`、`table=1`、`blockquote=1`，列表项 `检查 win-75 的 SSH/WinRM 登录账号是否可用…` 里的空格都在）、`Screenshot` 真的回 PNG 且面板里出现了带真像素的图片卡片（`naturalWidth 1280 / naturalHeight 720`，与 MCP 报的 `Screenshot Size` 一致）、工具调用折叠区**默认展开**（能直接看到「成功 observe_computer 157ms」）。横向几何：面板 400px、`.bastion-cu-body` 的 `scrollWidth == clientWidth`（399px），气泡与示例标签都没溢出。截图见 [computeruse-panel-welcome.png](screenshots/computeruse-panel-welcome.png)（空态）、[computeruse-panel.png](screenshots/computeruse-panel.png)（列表 + 表格真的渲染出来）、[computeruse-panel-tool-call.png](screenshots/computeruse-panel-tool-call.png)（工具调用卡片与默认展开的折叠区）。面板本身仍由 RDP 侧边栏的 **49** 个前端单测兜底（部署向导另有 63 例，全仓前端 12 文件 182 例全绿）。**仍未验证**：真实 RDP 会话里展开/收起时画布 resize 与远端分辨率联动。

## 用 Docker 部署（Linux 容器）

这一章讲怎么用 Docker 跑堡垒机。镜像是 **Linux 容器**镜像，两阶段构建：先用 `node:22-bookworm-slim` 把前端 `ant-design-pro` 构建出 `dist`，再拷进 `python:3.13-slim-bookworm` 运行时镜像；宿主机不需要装 Python 或 Node。

### 前提：能跑 Linux 容器

| 要求 | 说明 |
| --- | --- |
| 宿主 | Docker Desktop（WSL2 后端）、Linux 服务器、群晖等 NAS 都可以 |
| 容器类型 | **Linux 容器**（不是 Windows 容器模式） |
| 架构 | `linux/amd64`；Debian slim 基础镜像也有 arm64，Apple Silicon / ARM 服务器可以直接构建 |
| 本机依赖 | 不需要 Python、Node；构建与运行都在镜像里 |

确认 Docker 当前是 Linux 容器：

```bash
docker info --format '{{.OSType}}'
```

应返回 `linux`。如果返回 `windows`，说明 Docker Desktop 还停在 Windows 容器模式：托盘图标右键 →「Switch to Linux containers...」，切过来再重试。

### 功能边界：Windows 专属能力用不了

镜像基于 Debian，下列能力**在容器里不可用**，别当成「装了就能用」：

| 功能 | 在 Linux 镜像里的状态 |
| --- | --- |
| WinRM 资产 | 不可用。连 Windows 目标机走 WinRM 的那条链路没有实现 |
| ComputerUse 主机代理 | 不可用。它依赖 Windows 目标机上的 MCP 与桌面会话 |
| Rust RDP 网关扩展模块 | 不可用。`bastion-rdp-gateway.exe` 是 Windows 程序，装进容器也起不来；4489 只是预留端口 |

正常可用：SSH 资产（网页终端、SFTP 文件管理）、命令与文件策略、四类审计、会话回放、Web UI，以及扩展模块的界面与 js 模式页面。需要 WinRM、ComputerUse 或原生 RDP 网关的，用 Windows 主机按本地部署方式安装。

### 构建镜像

在仓库根目录构建。PowerShell：

```powershell
cd 你的项目目录
docker build -t autoops-bastion:latest .
```

bash / zsh：

```bash
cd /path/to/AutoOps
docker build -t autoops-bastion:latest .
```

- 首次构建要拉 `node:22-bookworm-slim` 与 `python:3.13-slim-bookworm` 两个基础层并装前后端依赖，耗时取决于网络。
- 前端在镜像内用 Node 22 构建，本机不需要 Node。
- `.dockerignore` 已排除 `node_modules`、`dist`、`instance`、`.git`、`docs`、`*.mod.ops_ext`，构建上下文很小。
- `npm ci` 与 `pip install` 都要联网；公司网络需要给 Docker 配代理或镜像源。

### 运行

PowerShell：

```powershell
docker run -d --name autoops `
  -p 5000:5000 -p 2222:2222 -p 4489:4489 `
  -v autoops-data:/app/data `
  autoops-bastion:latest
```

bash / zsh：

```bash
docker run -d --name autoops \
  -p 5000:5000 -p 2222:2222 -p 4489:4489 \
  -v autoops-data:/app/data \
  autoops-bastion:latest
```

- `--name autoops` 是容器名，后面的 `exec` / `logs` / `inspect` 都按这个名字写；compose 起的容器名是 `autoops-bastion`。
- `-p 5000:5000` Web/API，`-p 2222:2222` SSH 网关，`-p 4489:4489` 预留给 RDP 网关模块（Linux 镜像里没有可用的网关程序）。
- `-v autoops-data:/app/data` 把数据目录挂到命名卷；**不挂卷 = 删容器即丢数据**。
- 入口脚本 `/app/docker/entrypoint.sh` 会建好 `/app/data/instance`、打印监听地址与 Python 版本，再 `cd /app/bastion-backend` 执行 `python run.py --host 0.0.0.0 --port 5000 --gateway-host 0.0.0.0 --gateway-port 2222`。
- 镜像里 `TZ` 默认 `Asia/Shanghai`；要改时区用 `-e TZ=UTC` 这类值。

### 用 Docker Compose

仓库根的 `docker-compose.yml` 已经配好端口、卷、时区和健康检查：

```bash
docker compose up -d --build
docker compose logs -f
docker compose down
```

- `up -d --build` 构建并后台启动；改代码或 Dockerfile 后重跑这一条。
- `logs -f` 实时看日志，`Ctrl+C` 只退出日志，不停容器。
- `down` 停止并删除容器，**命名卷 `autoops-data` 保留**；`down -v` 才会连卷一起删，数据一起没。
- compose 里的容器名是 `autoops-bastion`（不是 `autoops`），`docker exec` / `docker inspect` 时注意替换。
- 服务设了 `restart: unless-stopped`，Docker 重启后容器会自己起来。

### 首次登录

浏览器打开 `http://localhost:5000`，用初始管理员 `admin` / `admin123` 登录，**首次登录会强制改密**。

改不了密、或忘了管理员口令，进容器重设：

```bash
docker exec -it autoops python run.py --reset-admin
```

如果提示找不到 `run.py`，带上工作目录：

```bash
docker exec -w /app/bastion-backend -it autoops python run.py --reset-admin
```

compose 部署把 `autoops` 换成 `autoops-bastion`。

### 端口

| 端口 | 用途 | 说明 |
| --- | --- | --- |
| `5000` | Web UI + REST API | 浏览器访问 `http://<主机IP>:5000`，健康检查 `/api/health` |
| `2222` | SSH 网关 | `ssh -p 2222 <堡垒机用户>@<主机>`，登录后只列有权限的主机 |
| `4489` | RDP 网关（预留） | 默认不装；Linux 镜像没有可用的网关程序，模块装了也起不来 |

### 数据与备份

所有运行数据都在卷 `autoops-data` 里，对应容器内的 `/app/data`；真正的内容在 `/app/data/instance/`：

| 路径 | 内容 |
| --- | --- |
| `bastion.db` | SQLite 库：用户、主机、授权、策略、审计 |
| `secret.key` / `fernet.key` / `gateway_host_rsa.key` | 会话签名、资产口令加密、SSH 网关主机密钥 |
| `rdp_recordings/` | WebRDP 会话录像 |
| `modules/` | 已安装的扩展模块 |

- 备份就是备份这个卷：`docker volume inspect autoops-data` 看卷的信息；也可以 `docker cp autoops:/app/data ./autoops-data-backup` 把目录整个拷出来。
- 换机器时，把 `-v` 指到同一个卷，或者把 `/app/data` 整个目录拷到新机器的卷里。
- 密钥跟着卷走：卷丢了，已存的资产口令就解不开。
- **不挂卷（或删掉 compose 的 `volumes:`）就没有持久化位置：删容器数据即丢。** `docker compose down -v` 也会删卷。

三种给法：

| `AI_ENABLED` | `1` | 设成 `0` 关闭 AI 运维 |
| `DEEPSEEK_API_KEY` | 空 | AI 凭据；不填时 `/api/ai/chat` 返回 400 `AI_NOT_CONFIGURED` |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 兼容 OpenAI 协议的中转地址 |
| `AI_MODEL` | `deepseek-flash` | 模型名 |
| `BASTION_ADMIN_USERNAME` / `BASTION_ADMIN_PASSWORD` | `admin` / `admin123` | 只在首次建库时创建管理员 |

- 密钥类（`BASTION_SECRET_KEY` / `BASTION_JWT_SECRET` / `BASTION_FERNET_KEY`）留空最省事：首次启动自动生成并存在卷里；改这些值会让已有登录态失效、已存口令解不开。
- 真实环境变量优先于 `.env`，`docker run -e` / compose 里给的值不会被 `.env` 覆盖。
- `.env` 不要提交。`bastion-backend/.env` 已在 `.gitignore` 里；如果放在仓库根目录用 `--env-file .env`，根目录的 `.env` **不在**忽略列表里，提交前先看 `git status`。

### 健康检查与日志

```bash
docker inspect --format '{{.State.Health.Status}}' autoops   # healthy / starting / unhealthy
docker logs -f autoops
curl http://localhost:5000/api/health
```

- `HEALTHCHECK` 每 30 秒用容器内的 Python 请求一次 `http://127.0.0.1:5000/api/health`，超时 10 秒；启动后前 60 秒是 `starting`，连续失败 3 次才转 `unhealthy`。
- PowerShell 里的 `curl` 是 `Invoke-WebRequest` 的别名，要看原始响应请用 `curl.exe`。
- 启动日志会打印 Web/API、健康检查、SSH 网关地址与数据目录；compose 部署用 `docker compose logs -f` 看同一份日志，容器名换成 `autoops-bastion`。

### 扩展模块

系统**不预装任何扩展模块**（全新实例是 0 个模块）。需要什么，登录后台 →「系统设置 → 扩展模块」上传：

| 模块包（仓库根目录） | 说明 |
| --- | --- |
| `hello-bastion-1.1.1.mod.ops_ext` | 官方示例模块 |
| `js-demo-1.0.1.mod.ops_ext` | 官方 JS 示例模块 |
| `rdp-gateway-1.2.2.mod.ops_ext` | RDP 网关；Linux 镜像里装得上但起不来（网关是 Windows exe），4489 只是预留 |

- 模块装在数据卷的 `/app/data/instance/modules/` 里，重建容器、升级镜像都不会丢。
- `.dockerignore` 把 `*.mod.ops_ext` 排除在构建上下文外，所以这些包是运行时上传，不打进镜像。

### 升级

```bash
docker compose build --pull
docker compose up -d
```

- 数据卷不动；`up -d` 会用新镜像重建容器。
- 跨大版本升级前先备份卷（见「数据与备份」）。
- 用 `docker run` 的：重新 `docker build` 后 `docker stop autoops`、`docker rm autoops`，再用同一条带 `-v autoops-data:/app/data` 的命令启动。

### 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| `docker info --format '{{.OSType}}'` 返回 `windows` | Docker Desktop 还停在 Windows 容器模式；托盘图标右键 →「Switch to Linux containers...」 |
| 5000 端口被占用 | 换映射：`-p 5001:5000`（compose 改 `ports`），浏览器开 `http://localhost:5001`；Web UI 里的跳转不受影响 |
| 构建卡在 `npm ci` / `npm run build` | 网络或代理问题，给 Docker 配好代理/镜像源后重试。备选路径：先在宿主 `npm run build`，让构建直接用现成的 `dist`（需要同步调整 `.dockerignore` 与 Dockerfile，不是默认做法） |
| 健康状态一直 `starting` 或 `unhealthy` | 先 `docker logs` 看后端有没有起来；刚启动的 `starting` 最多等 60 秒；再 `curl http://localhost:5000/api/health` |
| 容器时区不对 | 镜像默认 `TZ=Asia/Shanghai`，要改时区用 `-e TZ=UTC` 这类值（或改 compose 的 `environment:`） |
| 4489 连不上 | Linux 镜像没有 RDP 网关程序，这是预期行为；需要原生 RDP 网关请用 Windows 主机部署 |
| WinRM / ComputerUse 用不了 | Linux 镜像不包含这些 Windows 专属能力；用 Windows 主机按本地部署方式安装 |
| 删容器后数据没了 | 启动时没挂卷；用 `-v autoops-data:/app/data` 重新起，数据只在卷里 |
| 登录后改不了密 | `docker exec -it autoops python run.py --reset-admin`（见「首次登录」的工作目录写法） |

## 用 Docker 部署（Windows 容器）

Linux 镜像在 Debian 上跑，Windows 专属能力用不了；这个变体改用 Windows 基础镜像（`Dockerfile.windows`），把 WinRM、ComputerUse 和 RDP 网关都保留下来。代价是基础镜像大得多（合计约 10GB），构建也更慢。

### 与 Linux 镜像的能力差异

| 能力 | Linux 镜像 | Windows 镜像 |
| --- | --- | --- |
| SSH 资产、命令/文件策略、四类审计、会话回放、Web UI、扩展模块 | 可用 | 可用 |
| WinRM 资产 | 不可用 | 可用 |
| ComputerUse 主机代理 | 不可用 | 可用 |
| Rust RDP 网关（`bastion-rdp-gateway.exe`，4489） | 不可用 | 可用 |

### 前提与检查

| 要求 | 说明 |
| --- | --- |
| 宿主 | Windows 11 Pro/Enterprise（24H2+ 用 `ltsc2025`，旧 build 用 `ltsc2022`）或 Windows Server 2022/2025 |
| 容器类型 | Windows 容器（不是 Linux 容器模式） |
| 隔离级别 | Windows 11 客户端必须 `process`；默认 Hyper-V 隔离会报 `Invalid Signature` |
| 宿主 build | 要 ≥ 基础镜像 build（`ltsc2025` = 10.0.26100，`ltsc2022` = 10.0.20348） |
| 网络 | 首次构建要下载约 10GB 基础镜像，网络要稳 |

启用容器功能（管理员 PowerShell，执行后重启）：

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName $("Microsoft-Hyper-V","Containers") -All
```

确认当前是 Windows 容器：

```powershell
docker info --format '{{.OSType}}'      # 应为 windows
docker context ls                       # 应有 desktop-windows
```

返回 `linux` 时，在 Docker Desktop 托盘图标右键 →「Switch to Windows containers...」。

### 构建镜像

在仓库根目录构建：

```powershell
cd D:\Desktop\AutoOps
docker build --isolation=process -f Dockerfile.windows -t autoops-bastion:windows .
```

- `--isolation=process` 不能省：Windows 11 客户端用默认 Hyper-V 隔离会在 `hcs::CreateComputeSystem` 报 `Invalid Signature.`。
- 首次要拉 `servercore:ltsc2025` 与 `python:3.13-windowsservercore-ltsc2025`，合计约 **10GB**。
- `mcr.microsoft.com` 拉不动时换镜像源重建：

```powershell
docker build --isolation=process -f Dockerfile.windows -t autoops-bastion:windows . `
  --build-arg BASE_REGISTRY=mcr.m.daocloud.io `
  --build-arg PYTHON_REPOSITORY=docker.m.daocloud.io/library/python
```

- `BASE_REGISTRY` 换的是 `windows/servercore` 那一层；`PYTHON_REPOSITORY` 换的是 Python 基础镜像仓库（默认 `python`，即 Docker Hub；换成你能拉通的仓库）。
- 宿主 build 比 `ltsc2025` 旧时用 `--build-arg BASE_TAG=ltsc2022` 重建；镜像与宿主 build 不匹配会起不来。
- 前端在镜像内用 Node 22.20.0 的 zip 构建，本机不需要装 Node。

### 运行

```powershell
docker run -d --name autoops-win --isolation=process `
  -p 5000:5000 -p 2222:2222 -p 4489:4489 `
  -v autoops-data:C:\data `
  autoops-bastion:windows
```

- `--isolation=process` 与构建时保持一致；Windows Server 宿主默认可能就是 process，但显式写更稳。
- `-v autoops-data:C:\data` 挂数据卷；**不挂卷 = 删容器即丢数据**。
- 入口脚本 `C:\app\docker\entrypoint.ps1` 会建好 `C:\data\instance`、打印地址，再 `Set-Location C:\app\bastion-backend` 执行 `python run.py --host 0.0.0.0 --port 5000 --gateway-host 0.0.0.0 --gateway-port 2222`。
- 容器名是 `autoops-win`；compose 起的容器名是 `autoops-bastion-windows`。

### 用 Docker Compose

```powershell
docker compose -f docker-compose.windows.yml up -d --build
docker compose -f docker-compose.windows.yml logs -f
docker compose -f docker-compose.windows.yml down
```

- 文件里已经写了 `isolation: process`、端口 5000/2222/4489、卷 `autoops-data:C:\data` 和 `BASE_TAG: ltsc2025`。
- 宿主 build 旧时把 `build.args.BASE_TAG` 改成 `ltsc2022` 再 `up -d --build`。
- `down` 只删容器，卷保留；`down -v` 连卷一起删。

### 首次登录

浏览器打开 `http://localhost:5000`，初始管理员 `admin` / `admin123`，首次登录强制改密。

改不了密或忘了口令：

```powershell
docker exec -it autoops-win python run.py --reset-admin
```

提示找不到 `run.py` 时带上工作目录：

```powershell
docker exec -w C:\app\bastion-backend -it autoops-win python run.py --reset-admin
```

compose 部署把 `autoops-win` 换成 `autoops-bastion-windows`。

### 数据卷与备份

所有运行数据都在卷 `autoops-data` 里，对应容器内的 `C:\data`；实际内容在 `C:\data\instance\`：

| 路径 | 内容 |
| --- | --- |
| `bastion.db` | SQLite 库：用户、主机、授权、策略、审计 |
| `secret.key` / `fernet.key` / `gateway_host_rsa.key` | 会话签名、资产口令加密、SSH 网关主机密钥 |
| `rdp_recordings\` | WebRDP 会话录像 |
| `modules\` | 已安装的扩展模块 |

- 备份：`docker cp autoops-win:C:\data .\autoops-data-backup`，或按你惯用的卷备份方式整个拷走。
- 换机器时把 `-v` 指到同一个卷，或把 `C:\data` 拷到新机器的卷里。
- 密钥跟着卷走：卷丢了，已存的资产口令就解不开。
- **不挂卷（或删掉 compose 的 `volumes:`）就没有持久化位置：删容器数据即丢。** `down -v` 也会删卷。

### RDP 网关模块在容器里的用法

Windows 镜像可以跑官方的 Rust 网关，步骤和本地部署一致：

1. 按「编译 RDP 网关并打包成扩展模块」编译出 `bastion-rdp-gateway.exe`，放进 `modules-src/rdp-gateway/bin/`，打包成 `rdp-gateway-1.2.2.mod.ops_ext`。
2. 登录后台 →「系统设置 → 扩展模块」上传安装并启用。
3. 模块进程从模块目录的 `bin\bastion-rdp-gateway.exe` 启动（容器里落在 `C:\data\instance\modules\` 下），监听 4489；`docker run` / compose 已经映射 `4489:4489`。
4. mstsc 连 `<宿主IP>:4489`，网关按已授权的 RDP 资产转发。

- 网关进程跟着容器走：容器停了它就停；`docker logs` 里能看到它的启动输出。
- 想自定义 exe 路径或端口，用环境变量 `BASTION_RDP_GATEWAY_BIN`、`RDP_GATEWAY_PORT`（见 `bastion-backend\.env.example` 第 10 节）。

### 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 构建或启动报 `hcs::CreateComputeSystem ...: Invalid Signature.` | 用了默认 Hyper-V 隔离；构建与运行都加 `--isolation=process`（compose 已内置） |

| 构建卡在 nodejs.org 下载 | 取 Node 22.20.0 zip 超时；给 Docker 配代理后重试 |
| 5000 端口被占用 | 改映射 `-p 5001:5000`，浏览器开 `http://localhost:5001` |

| 删容器后数据没了 | 没挂卷；用 `-v autoops-data:C:\data` 重新起 |
