**为什么把 MCP 关在回环里再映射出来**：Windows-MCP 的 `mcp` 包默认开着 DNS-rebinding 防护，`allowed_hosts` 只认回环（`127.0.0.1:*` / `localhost:*` / `[::1]:*`），所以堡垒机隔着 portproxy 用 `Host: 192.168.0.75` 去访问会被拒（真机报 `Invalid host header`）。最终的做法是**客户端显式声明 `Host: 127.0.0.1:<端口>`**——portproxy 本来就终结到 127.0.0.1，真正的门禁交回给「防火墙白名单 + Bearer 密钥」这两道；目标机对外也始终只开放一个映射端口。

**会话隔离这一条要讲清楚**：Windows-MCP 的截图与界面自动化只认「它自己所在的那个登录会话」。目标机**没有交互式登录**时 MCP 跑在会话 0，PowerShell、文件、进程类工具都能用，但**截图和界面自动化是空的**；用户 RDP 登录之后，开机自启脚本会用「端口接管脚本」把 MCP 抢到你的桌面会话（**同一个端口，侧边栏不用改地址**）。

**速度上的一条实测**：`pip install windows-mcp` 直连 pypi.org 约 **18 分钟**，清华源约 **5 秒**，所以向导默认填清华源。
